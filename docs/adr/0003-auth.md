# ADR 0003 — บัญชีผู้ใช้ รหัสผ่าน และ session

- สถานะ: ตัดสินแล้ว (2026-10-28)

## บริบท
เจ้าของต้องการรหัสผ่านที่ปลอดภัยจน Admin ก็มองไม่เห็น ต้องมีการสมัครบัญชีและการกู้รหัสผ่าน
**และไม่ใช้อีเมล**: แจ้งเตือนในแอปเท่านั้น และให้ Admin เป็นผู้รีเซ็ตรหัสผ่าน

## ตัดสินใจ
- **รหัสผ่าน**: PBKDF2-HMAC-SHA256 600,000 รอบ (ตาม OWASP 2023) ด้วย `Rfc2898DeriveBytes.Pbkdf2` ที่มีใน .NET
  - salt 16 ไบต์ hash 32 ไบต์ เก็บเป็น `v1.{iter}.{salt}.{hash}` เพื่อให้เพิ่มจำนวนรอบภายหลังได้ และ rehash ตอน login
  - เทียบค่าด้วย `CryptographicOperations.FixedTimeEquals`
  - ความยาวขั้นต่ำ 10 ตัวอักษร และตรวจกับรายการรหัสยอดนิยมที่ฝังไว้ในโปรแกรม
- **Session**: เก็บ session ไว้ที่ฝั่งเซิร์ฟเวอร์ (ตาราง `Sessions`) และ cookie ถือเพียง token สุ่ม 32 ไบต์ ส่วนฐานข้อมูลเก็บแค่ SHA-256 ของ token
  - cookie ตั้งเป็น `HttpOnly; Secure; SameSite=Strict; Path=/`
  - หมดอายุเมื่อไม่ใช้งาน 12 ชั่วโมง และหมดอายุแน่นอนที่ 7 วัน
  - ไม่ใช้ JWT ใน localStorage แบบ ERP เพราะเว็บนี้มีหน้าสาธารณะอยู่ในโดเมนเดียวกัน token ที่ JS อ่านได้จึงเสี่ยงกว่า และการเก็บ session ฝั่งเซิร์ฟเวอร์ทำให้เพิกถอนได้ทันที
- **CSRF**: คำขอที่เปลี่ยนสถานะต้องมี header `X-CSRF` ที่ตรงกับ token ของ session และต้องไม่เป็น `SameSite=Strict` เพียงอย่างเดียว
- **สมัครบัญชี**: กรอกชื่อ อีเมล ประเภทบุคคล และรหัสผ่าน → `PendingApproval` → Admin หรือผู้มีสิทธิ์อนุมัติ แล้วผูกหรือสร้างระเบียน Person (ไม่มีการยืนยันอีเมล)
- **ลืมรหัสผ่าน**: ผู้ใช้ส่งคำขอจากหน้า login → แจ้ง Admin ในแอป → Admin ยืนยันตัวตนนอกระบบ (เช่น เจอตัวหรือโทร) → ระบบสร้างรหัสใช้ครั้งเดียว แสดงให้ Admin **ครั้งเดียว** แล้วเก็บเพียง hash
  - เมื่อผู้ใช้ login ด้วยรหัสนี้ ระบบบังคับเปลี่ยนรหัส และตัด session เก่าทิ้งทั้งหมด
  - Admin ไม่เคยเห็นรหัสที่ผู้ใช้ตั้งเอง
- **2FA**: TOTP (RFC 6238, แอป Authenticator) เขียนเองด้วย HMACSHA1 ของ .NET
  - บังคับสำหรับ Admin และผู้ที่อยู่ในสายอนุมัติเงิน คนอื่นเปิดใช้ได้ตามสมัครใจ
  - มีรหัสสำรอง 10 ชุด
- **บัญชีขาจร**: มี `ExpiresAt` เมื่อถึงวันหมดอายุ worker จะเปลี่ยนสถานะเป็น `Expired` และตัด session โดยข้อมูลยังอยู่ครบ
- **จำกัดการเดารหัส**: login ผิด 10 ครั้งใน 5 นาทีต่อ IP หรือต่อ username จะได้ 429 และบันทึกลง ChangeLog
- **Admin คนแรก** (ดร.กสาน จันทร์โต): seed ครั้งแรกจะสร้างรหัสใช้ครั้งเดียวและพิมพ์ออกทาง console บน Mac เท่านั้น
  - production ไม่ยอมเริ่มทำงานถ้ายังมีบัญชีที่ใช้รหัสใช้ครั้งเดียวที่สร้างก่อน deploy

## ผลที่ตามมา
- Admin ต้องคอยดูคำขอรีเซ็ตรหัส ซึ่งรับได้เพราะผู้ใช้มีราว 50 คนต่อปี
