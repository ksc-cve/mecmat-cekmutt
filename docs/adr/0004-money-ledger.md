# ADR 0004 — การเงินเป็นตัวเลข: บัญชีซ้อนกัน + สมุดบัญชีที่แก้ไม่ได้

- สถานะ: ตัดสินแล้ว (2026-10-28)

## บริบท
เจ้าของต้องการ "ขอเบิก ขอจ่ายเชิงตัวเลข" โดย **ไม่ออกเอกสารหรือแบบฟอร์ม และไม่ใช่ระบบจ่ายเงินจริง**
แหล่งเงินต้องแยกเป็นบัญชีย่อยซ้อนกันได้ และต้องดูยอดคงเหลือและงบเทียบกับที่ใช้จริงได้

## ตัดสินใจ
- **จำนวนเงินเก็บเป็น `long` หน่วยสตางค์** เพราะ EF Core กับ SQLite เก็บ decimal เป็น TEXT ทำให้ SUM/ORDER ในฐานข้อมูลผิด และ double ก็ปัดเศษผิด
- **Account เป็นต้นไม้** (`ParentAccountId`) ซ้อนกันได้ไม่จำกัดชั้น เช่น แหล่งเงิน → โครงการ → หมวดงบ NRIIS → บัญชีย่อย
  - ยอดของบัญชีแม่คือผลรวมของบัญชีลูกทุกชั้น คำนวณตอนอ่าน ไม่เก็บซ้ำ
  - รายการเงินลงได้เฉพาะบัญชีปลายสุด (leaf) เพื่อไม่ให้ยอดซ้อนกัน
- **LedgerEntry แก้ไขและลบไม่ได้** ทุกรายการมี `FromAccountId` และ `ToAccountId` (null หมายถึงเงินจากหรือไปนอกระบบ) และจำนวนเงินต้องเป็นบวกเสมอ
  - การแก้ไขทำโดยลงรายการกลับรายการ (`ReversesEntryId`) แล้วลงรายการใหม่
  - ร่องรอยครบเสมอ ซึ่งผู้ตรวจสอบต้องการ
- **MoneyRequest** มี 5 ประเภท: ขอเบิก (คืนเงินผู้สำรองจ่าย), ขอจ่าย (จ่ายผู้รับ), ขอยืม, ล้างเงินยืม และขอโอนระหว่างบัญชี
  - มีรายการย่อยเป็นตัวเลข แนบไฟล์หลักฐานได้ แต่ไม่สร้างไฟล์เอกสาร
- **ยอดใช้ได้ = ยอดคงเหลือ − คำขอที่อนุมัติแล้วแต่ยังไม่ลงบัญชี − คำขอที่รออนุมัติ** ระบบตรวจทั้งตอนส่งและตอนอนุมัติขั้นสุดท้าย บัญชีติดลบไม่ได้ เว้นแต่ตั้ง `AllowNegative`
- **เงินยืม**: ยอดค้างคือยืม − ล้าง − คืน ครบกำหนดตามที่ตั้งไว้ในคำขอ (ค่าเริ่มต้น 30 วัน แก้ใน Settings ได้) และมีการเตือนในแอปก่อนครบกำหนด 3 วันและเมื่อเลยกำหนด
- **Budget vs Actual**: งบเก็บที่ `AccountBudget` (บัญชี × ปีงบประมาณ) ส่วนยอดใช้จริงคำนวณจาก ledger
