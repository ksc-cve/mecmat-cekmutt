# ADR 0005 — ระบบอนุมัติที่ตั้งค่าได้

- สถานะ: ตัดสินแล้ว (2026-10-28)

## บริบท
เจ้าของต้องการ "โครงสร้างอำนาจกำหนดในระบบได้" เช่น อนุมัติจ่ายเงินโดยผู้มีอำนาจสูงกว่า
ERP ใช้หลัก "อนุมัติเป็นหมายเหตุ ไม่ขวาง" ซึ่งใช้กับเงินไม่ได้

## ตัดสินใจ
- **โครงสร้างอำนาจเป็นข้อมูล ไม่ใช่โค้ด** มีองค์ประกอบดังนี้
  - `GroupPosition` คือตำแหน่งในกลุ่ม เช่น หัวหน้ากลุ่ม รองหัวหน้า ผู้จัดการการเงิน ผู้ดูแลแล็บ
  - `PositionAssignment` คือใครดำรงตำแหน่งใด ตั้งแต่เมื่อใดถึงเมื่อใด
  - `ApprovalPolicy` เลือกใช้ตามประเภทคำขอ × ช่วงวงเงิน × ขอบเขตบัญชีหรือโครงการ (มีผลกับบัญชีลูกทั้งหมด) × ลำดับความสำคัญ
  - `ApprovalPolicyStep` ระบุผู้อนุมัติแต่ละขั้น เป็นตำแหน่ง บุคคล บทบาทในโครงการ (เช่น PI) ผู้ดูแลบัญชี หรือหัวหน้าของผู้ขอ
  - แต่ละขั้นกำหนดได้ว่า "คนใดคนหนึ่ง" หรือ "ทุกคน" ต้องอนุมัติ
  - `Delegation` คือการมอบอำนาจแทนชั่วคราว
- **ผู้ขออนุมัติคำขอของตัวเองไม่ได้** ถ้าผู้ขอเป็นผู้อนุมัติในขั้นนั้นเอง ระบบข้ามไปให้ผู้ที่มีอำนาจถัดขึ้นไป
- **ตอนส่งคำขอ ระบบ snapshot นโยบายไว้** การแก้นโยบายภายหลังจึงไม่เปลี่ยนเส้นทางของคำขอที่ส่งไปแล้ว
- **สองแบบ**
  - **ขวาง (blocking)**: คำขอเงินทุกประเภท การจองทรัพยากรที่ตั้ง `RequiresApproval` และการสมัครบัญชี ยังไม่อนุมัติก็ยังไม่เกิดผล
  - **หมายเหตุ (annotation)**: การเผยแพร่ข่าวหรือผลงาน และการแก้ประวัติ ทำได้เลยและระบบบันทึกว่าใครรับรอง
- ทุกการตัดสินใจ (อนุมัติ/ไม่อนุมัติ/ส่งกลับแก้ไข) ต้องบันทึกชื่อผู้ทำ ผู้ที่ทำแทน (ถ้ามี) ความเห็น และเวลา ลงใน `ApprovalAction` และ ChangeLog
- ถ้าไม่มีนโยบายใดตรงกับคำขอ **ระบบไม่ยอมให้ส่ง** และบอกผู้ขอว่าต้องให้ Admin ตั้งนโยบายก่อน ไม่ปล่อยผ่านแบบเงียบ ๆ

## ค่าเริ่มต้นที่ seed (แก้ได้)
- คำขอเงิน ≤ 5,000 บาท: PI ของโครงการอนุมัติ
- คำขอเงิน 5,000.01–50,000 บาท: PI → หัวหน้ากลุ่ม
- คำขอเงิน > 50,000 บาท: PI → ผู้จัดการการเงิน → หัวหน้ากลุ่ม
- คำขอที่ไม่ผูกกับโครงการ: ผู้ดูแลบัญชี → หัวหน้ากลุ่ม
