# MECMAT — สิทธิ์การเข้าถึง (ร่างสำหรับเจ้าของตรวจ)

## 1. รูปแบบสิทธิ์
แต่ละโมดูลมีสิทธิ์สองแกน (แนวคิดเดียวกับ ERP แต่ลดเหลือที่จำเป็น)
- **Action**: `None` < `View` < `Create` < `Edit` < `Manage` (Manage = ลบ/กู้คืน/ตั้งค่าโมดูล)
- **Scope**: `Related` (เฉพาะข้อมูลที่เกี่ยวกับตัวเอง) หรือ `All`

สิทธิ์จริงของผู้ใช้ = สิทธิ์สูงสุดจากทุก Role ที่ถือ แล้วแทนด้วย `UserPermissionOverride` (ถ้ามี)
`IsAdmin` = ทุกอย่าง แต่ **ยังมองไม่เห็นรหัสผ่านและ TOTP secret** และการเปิดดูข้อมูลอ่อนไหวทุกครั้งถูกบันทึก

**การอนุมัติไม่ใช่สิทธิ์ของโมดูล** — ผู้อนุมัติมาจาก ApprovalPolicy (ตำแหน่ง/บุคคล/บทบาทในโครงการ) ดู [adr/0005-approvals.md](adr/0005-approvals.md)

### "Related" หมายถึง
| โมดูล | Related = |
|---|---|
| บุคลากร | ระเบียนของตัวเอง + นักศึกษาที่ตัวเองเป็นที่ปรึกษา + สมาชิกในโครงการที่ตัวเองเป็น PI/CoPI |
| ผลงาน | ผลงานที่ตัวเองเป็นผู้แต่ง หรือเป็นผลงานของโครงการที่ตัวเองเป็นสมาชิก |
| โครงการ | โครงการที่ตัวเองเป็นสมาชิก (บทบาทในโครงการกำหนดว่าแก้อะไรได้ — ข้อ 3) |
| การเงิน | คำขอของตัวเอง + บัญชีที่ตัวเองเป็นผู้ดูแล + บัญชีของโครงการที่ตัวเองเป็น PI/CoPI/FinanceContact + คำขอที่ตัวเองอยู่ในสายอนุมัติ |
| ครุภัณฑ์/วัสดุ | รายการที่ตัวเองเป็นผู้ดูแล หรือกำลังยืมอยู่ |
| การจอง | ดูปฏิทินทั้งหมดได้ (เห็นว่าไม่ว่าง) แต่เห็นรายละเอียดเฉพาะการจองของตัวเองและโครงการตัวเอง |
| งาน/ประชุม | งานที่ได้รับมอบหมายหรือสร้างเอง, ประชุมที่ได้รับเชิญ, ของโครงการตัวเอง |
| เอกสาร | โฟลเดอร์ของตัวเอง + โฟลเดอร์โครงการที่เป็นสมาชิก + โฟลเดอร์ระดับกลุ่ม (Visibility=Group) |

## 4. หลักบังคับใช้ (จาก ERP)
- **ทุกการตรวจสิทธิ์ทำที่เซิร์ฟเวอร์** — หน้าจอเพียงซ่อนปุ่มที่เซิร์ฟเวอร์จะปฏิเสธ ("อย่าแสดงปุ่มที่กดแล้วโดนปฏิเสธ")
- รายการ (list) ถูกกรองตาม Scope ที่ query ไม่ใช่กรองหลังโหลด
- ทดสอบด้วย `tools/authcheck` ยิง API ด้วยบัญชีทุกบทบาท ตรวจทั้ง "ทำได้" และ "ต้องทำไม่ได้"
